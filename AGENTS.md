# Project commenting style

- Use short, simple comments that sound natural, like a college student wrote them.
- When creating or significantly editing a long, confusing, or important file,
  add a short summary at the top explaining its purpose. An existing clear
  module docstring is enough.
- Add brief function summaries and inline comments where database queries,
  API behavior, trade rules, or model calculations need explanation.
- Explain why a step matters instead of repeating obvious code. Skip extra
  comments in tiny or self-explanatory files.
- Keep comment-only work separate from changes to program behavior.
